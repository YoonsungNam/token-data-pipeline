**CSV 계약(§6.1)**: 헤더 `user_id,user_name,org,is_active,effective_from` — `org`는 `>` 구분 단일 컬럼(예: `A부문>X팀`), `is_active` 선택(기본 1), `effective_from` 선택(없으면 --effective-from, 그것도 없으면 기본 과거 기준일 `2020-01-01` 상수 — "이력 시작 이전 전부 유효" 의미 주석).

**검증 규칙(위반 시 stderr 요약 + exit 1 — 데이터 행 에코 금지, 행 번호·필드명만)**:
- user_id 빈 값 거부, org 빈 값·빈 세그먼트(`A>>B`, 선행/후행 `>`) 거부
- (user_id, effective_from) 파일 내 중복 거부
- effective_from/`--effective-from` 날짜 형식 검증
- `anon-*` user_id 행은 user_name을 **강제 빈 문자열로 치환** + stderr 카운트 보고(§6.1 — 거부가 아니라 강제)
- is_active ∈ {0,1}

**출력 SQL 계약(시드 3요소 + §7.2)**: (a) 헤더 주석 — 입력 파일명(경로 아님 — basename)·행수·기본 effective_from (생성 시각 없음 — 결정성), "실로스터 산출물은 레포 반입 금지" 경고, (b) chunk당 `INSERT INTO gpu_data.dim_token_user_org_dist (컬럼...) SELECT * FROM (SELECT ... UNION ALL ...) WHERE (user_id, effective_from) NOT IN (SELECT user_id, effective_from FROM gpu_data.dim_token_user_org_dist) SETTINGS insert_distributed_sync = 1;` — updated_at은 `now('Asia/Seoul')` 서버 함수(결정성은 SQL 텍스트 기준), org_path는 `['A부문','X팀']` 배열 리터럴(이스케이프 순서: `\` → `\\` **먼저**, 그다음 `'` → `\'` — 백슬래시 미처리 시 SQL 파손), org_depth=len, (c) 말미 검증 SELECT — 섹션 시작 주석은 seed 파일과 동일 리터럴 **`-- 검증: 결과가 비어야 정상`**(T3 sed 앵커) 뒤에, INSERT와 **동일 chunk_size로 분할된 검증문들**:
  - `dup_key`: 전역 (user_id, effective_from) count>1 노출
  - `missing_key`(chunk별): 파일 키 UNION 체인에서 `(user_id, effective_from) NOT IN (SELECT ... FROM dim)` — **누락 키 행을 직접 노출** (count 비교 아님 — 위반 행 식별 가능, max_query_size 256KiB 한계 회피)
  - `key_conflict`(chunk별): 파일 키와 **DB 기존 행의 내용 불일치** 노출(org_path/user_name/is_active 비교 — NOT IN 멱등 가드가 동일 키 정정을 조용히 스킵하는 것의 가시화. 주석: "동일 키 정정은 금지 — 새 effective_from 행 또는 §8.4 정정 절차". §6.1 '구간 검증'은 dup_key+key_conflict로 이행 — 사용자별 effective_from 중복·기존 이력과의 충돌 검출).
